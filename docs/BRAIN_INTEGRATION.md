# External brain — GitHub ↔ Google Drive integration

Spreadsheet: https://docs.google.com/spreadsheets/d/1Xi2wSER-vEIjy52FTKA5RvMXNnGrTxoYiEoPhyXw77c/edit

Authority precedence: current explicit user instruction > active song branch/Operating Order > bootstrapped AIVideoEdit OS from GitHub; Drive is *retrieval and evidence*, never authorization of an effect, branch, source image or film release.

After successful `python godrender_boot.py`:
1. Identify task image/material and expected animated behavior.
2. Search **CALLABLE CAPABILITIES** and **FX PIXEL APPLICATION ATLAS** for callable symbol, ROI, parameter signature and pixel operations.
3. Search **FX COMPOSITION RECIPES** for ordered image-layer/mask actions; use **RECOVERABLE RENDER LINEAGE** to find working methods from failed or rejected films, without reusing rejected art.
4. Search **PER-BRANCH PACKAGE REVIEW** for the original `repo@branch#commit`, exact script and Git blob SHA, original expected media and known failure mechanism.
5. Resolve the **live bootstrapped** canonical FX registry and status; require all actual FX execution gates. If the script is `upstream/recovered-song-tech`, treat it as historical, not production-approved.
6. Before production render output `repo SHA | branch | bootstrap PASS evidence | resolved FX / input image SHA / masks / parameters | gate | exact runner/job | resulting output SHA / QC`.
7. Record newly proven capabilities in the brain only after concrete run artifacts and human Director review, preserving failed stages.

The pinned GitHub-side branch snapshot (`config/brain_source_index.json`) contains source links for 100 indexed branch heads; it does not auto-update when GitHub branches move. User authorization to access any Drive content remains subject to existing permissions and tools. Never embed OAuth credentials or claim automatic synchronization.
