# GodRender — Native Production Guardrails

**Authority:** `SouthPaw302/GodRender` on the exact checked-out ref, with production policy taken from the attested `main` snapshot. This document applies to agents, Studio, ONNX/model workers, Jev, FX executors and processing runners. Imported `upstream/` files and the Drive External Brain are evidence/provenance, never executable policy authorities.

## Required startup and evidence

1. Identify the actual branch and commit. Read `AGENTS.md`, `PRIME_DIRECTIVE.md`, `SOUL.md` and the active project's operating order.
2. Run `python tools/verify_consolidation.py` and `python godrender_boot.py`. No production processing without the required verified native GodRender bootstrap attestation and the verified native GodRender PASS. Never fabricate a PASS, CI URL, hash, executed FX, proof or viewing claim.
3. Use GodRender-native session paths, schemas, environment variables and internal URIs. Historical serialized files may be imported only by an explicit validated conversion; they are never active runtime authorities.
4. Enforce `general/reusable/PRODUCTION_CONTRACT.json`, the production/workflow/recipe/FX guards, and applicable zero-drift and QC directives. Failure or missing required inputs means stop that action and report the blocker; never bypass or silently weaken a check.

## Preservation and processing

5. Approved source media, identity, shots, timing, edits and hashes are canon within the explicitly approved scope. Preserve originals and prior proofs. Rejected or unverified assets must not be silently reused, substituted or promoted. A user-approved change only changes the named scope.
6. Work is **media processing**, with rendering/export only where the declared processing step actually requires it. Select the real, available worker, model and FX implementation; record inputs, outputs, version, parameters, region/masks and evidence. Registration, integration or green CI alone does not prove media processing was run.
7. Run representative moving proofs and FX checks before expanding to sections or entire films. Keep technical PASS, creative acceptance and release authorization separate. Report exactly what media was reviewed.
8. Preserve song-specific isolation and individual branch provenance. Do not mutate other video repositories. Historical source, recovered techniques and Drive entries are lookup-only until expressly selected and verified for the current production.

## GitHub and release boundaries

9. GitHub Actions and runners execute scoped processing jobs and retain logs, proof artifacts and input/output hashes. Do not claim parallel jobs operated unless run IDs and artifacts exist. The External Brain is updated only when receipt-backed synchronization actually succeeds.
10. No silent commits to protected code, no bypassing a failed boot, no merging unverified migrations, no delivery-master overwrite and no release without current user authorization. Preserve source evidence and hashes; reject unconverted external production state rather than silently pretending it is native.
